## Background

기존 완료 흐름은 결과 요약, 주요 결정, 남은 위험과 회고를 입력하거나 건너뛰기를 선택해야 했다. 작은 Task까지 완료 모달을 거치면서 상태 정리 자체가 느려졌고, 사용자는 완료를 선택한 즉시 보드의 완료 열로 이동하는 흐름을 원했다.

## Decision

Task 완료는 별도 입력 없이 즉시 `done`으로 전이한다. 데이터베이스는 완료 시각과 revision을 갱신하고, 해당 Task가 집중 중이면 focus slot을 같은 statement 안에서 해제한다. 새 completion record와 evidence snapshot은 만들지 않는다. 기존 completion record는 과거 데이터 호환을 위해 보존한다.

## Options

| Option | Pros | Cons |
| --- | --- | --- |
| 즉시 완료 | 상태 정리의 마찰이 가장 낮고 작은 Task에도 일관됨 | 구조화된 회고와 완료 시점 evidence가 자동 축적되지 않음 |
| 완료 모달 유지 | 성과·결정·위험 검색 품질이 높음 | 완료할 때마다 입력 또는 건너뛰기 동작이 필요함 |
| 환경설정으로 선택 | 사용자별 유연성 | 정책과 테스트 경로가 이중화됨 |

**최종 결정:** 완료 모달을 제거하고 즉시 완료를 기본이자 유일한 흐름으로 사용한다.

## Consequences

- 일일 보고서는 completion record가 없는 완료 Task를 제목과 완료 시각으로 표시한다.
- 과거 구조화된 완료 기록 검색은 계속 동작하지만 새 기록은 추가되지 않는다.
- 상세한 회고가 필요하면 완료 전 Task 설명·체크포인트 또는 연결된 원본에 남겨야 한다.
